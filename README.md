# Personal Finance Agent

An AI agent that reads your bank statement, categorizes every transaction with a
model it trained itself, forecasts next month's spending, and answers questions
like *"Can I afford a ₹15,000 trip?"* by calling tools over your data.

**Live demo:** `https://<your-username>.github.io/finance-agent/` · **API:** `https://<your-render-app>.onrender.com/api/health`

## What it shows

| Area | What's inside |
|---|---|
| Web | React + TypeScript dashboard (Vite), charts (Recharts), FastAPI REST API, file upload, CORS, rate limiting, input validation |
| ML | TF-IDF character n-grams + Logistic Regression categorizer, honest evaluation on **unseen merchants**, trend + moving-average forecast |
| AI agent | LLM tool-calling loop (OpenAI-compatible API, e.g. Groq Llama 3.3), 5 typed tools, max-step guard, offline fallback |
| Engineering | 23 pytest tests, GitHub Actions CI, GitHub Pages deploy, Render blueprint, stateless privacy-first design |

## Architecture

```
Browser (GitHub Pages)                    API (Render, FastAPI)
┌───────────────────────┐   JSON/HTTPS   ┌──────────────────────────────────────┐
│ Upload CSV            │ ─────────────▶ │ /api/upload  parse → ML categorizer    │
│ Dashboard + charts    │ ◀───────────── │ /api/forecast  trend forecast          │
│ Fix wrong categories  │                │ /api/chat  agent loop:                 │
│ Chat with the agent   │ ─────────────▶ │   LLM ⇄ tools(spending_summary,        │
└───────────────────────┘                │   top_merchants, forecast,             │
  holds the data in memory               │   check_affordability, make_chart)     │
                                         └──────────────────────────────────────┘
                                           stores nothing; LLM key stays server-side
```

**How the agent works:** the question and the tool schemas go to the LLM. If it
asks for a tool, the backend runs that tool on the user's transactions and sends
the result back. This repeats (max 5 steps) until the LLM writes the answer. The UI
shows every tool call, so you can see *why* it answered what it did. Tools take
typed arguments (dates, a category from a fixed list, a number), never free-form
SQL, so the model can't run arbitrary queries. Without an API key, a keyword
router picks the tools instead, so the app (and the tests) still work offline.

## ML results

Training data is synthetic, generated by `app/data/generate.py` (3,000
bank-style descriptions such as `UPI/SWIGGY/482910`, `POS CITY FUEL STATION PUNE`).

| Evaluation | Accuracy |
|---|---|
| Random split (shops seen in training) | 98.8% |
| **Held-out shops (never seen in training)** | **92.4%** |

The second number is the honest one: a random split leaks the same merchants
into train and test. Big brands with no category clue in the name (`NETFLIX`
vs `SPOTIFY`) are the hard cases, so the UI marks low-confidence predictions
and lets the user correct them. Corrections are used by the agent right away.

## Run locally

```bash
# Backend (Python 3.9+)
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
python -m app.ml.train        # trains + prints metrics
python -m pytest -q           # 23 tests
python -m app.main            # http://127.0.0.1:8000  (loopback only)

# Frontend (Node 20+)
cd frontend
npm install
npm run dev                   # http://127.0.0.1:5173
```

Optional, to switch on the LLM: get a free key at [console.groq.com](https://console.groq.com)
and `export LLM_API_KEY=...` before starting the backend. Any OpenAI-compatible
API works via `LLM_BASE_URL` and `LLM_MODEL`.

## Deploy

1. **Backend → Render:** New → Blueprint → pick this repo (uses `render.yaml`).
   Set `LLM_API_KEY` and `ALLOWED_ORIGINS=https://<your-username>.github.io`.
2. **Frontend → GitHub Pages:** repo Settings → Pages → Source: *GitHub Actions*.
   Settings → Secrets and variables → Actions → Variables → add
   `API_URL=https://<your-render-app>.onrender.com`. Push to `main`.

Render's free tier sleeps after 15 minutes idle, so the first request takes ~30–60 s.
Open the site a minute before you demo it.
